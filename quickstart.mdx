---
title: "Quickstart"
description: "Run your first version bump in under a minute."
---

<Note>
  Bump is safe by default. Every command is a dry run unless you pass `-write`. You will always see the new version before anything is saved to disk.
</Note>

<Steps>
  <Step title="Install bump">
    Install bump using `go install` or download a pre-built binary for your platform.

    ```bash
    go install github.com/andreimerlescu/bump@latest
    ```

    See the [installation guide](/installation) for binary downloads and platform-specific instructions.
  </Step>

  <Step title="Create or locate a VERSION file">
    Bump reads from `./VERSION` in your current directory by default. Create one if it does not exist:

    ```bash
    echo "v1.0.2" > VERSION
    ```

    You can also point bump at a different file with the `-in` flag:

    ```bash
    bump -check -in package.json
    ```

    Supported file types: `VERSION`, `package.json`, `go.mod`, `Dockerfile`, `Chart.yaml`, `pom.xml`.
  </Step>

  <Step title="Check the current version">
    Read and validate the current version in your file:

    ```bash
    bump -check
    ```

    ```
    v1.0.2
    ```

    Bump exits with code `0` if the version is valid, or `1` if parsing fails.
  </Step>

  <Step title="Preview a bump (dry run)">
    Run a bump command without `-write` to see the result before saving:

    ```bash
    bump -patch
    ```

    ```
    Bumped v1.0.2 → v1.0.3
    ```

    Nothing is written to disk. Use this to verify the output looks correct before committing.
  </Step>

  <Step title="Write the bump to the file">
    Add `-write` to apply the change and save it:

    ```bash
    bump -patch -write
    ```

    ```
    Bumped v1.0.2 → v1.0.3 (saved to VERSION)
    ```
  </Step>

  <Step title="Verify the change">
    Confirm the file was updated:

    ```bash
    bump -check
    ```

    ```
    v1.0.3
    ```
  </Step>
</Steps>

## Available bump types

You can bump any version component individually:

| Flag | Example result |
|------|---------------|
| `-major` | `v1.0.3` → `v2.0.0` |
| `-minor` | `v1.0.3` → `v1.1.0` |
| `-patch` | `v1.0.3` → `v1.0.4` |
| `-alpha` | `v1.0.3` → `v1.0.3-alpha.1` |
| `-beta` | `v1.0.3` → `v1.0.3-beta.1` |
| `-rc` | `v1.0.3` → `v1.0.3-rc.1` |
| `-preview` | `v1.0.3` → `v1.0.3-preview.1` |

Pre-release flags can be combined with version flags. For example, `bump -patch -beta` bumps the patch and sets a beta pre-release in one step.

<Tip>
  Use `-json` to get machine-readable output for use in CI/CD pipelines:

  ```bash
  bump -patch -json
  ```

  ```json
  {
    "major": 1,
    "minor": 0,
    "patch": 4,
    "alpha": 0,
    "beta": 0,
    "rc": 0,
    "preview": 0,
    "version": "v1.0.4"
  }
  ```

  When used with `-check`, only the `version` field is returned: `{"version": "v1.0.3"}`.

  Note: `-json` controls the output format only. The version file is still written as plain text when `-write` is used.
</Tip>
